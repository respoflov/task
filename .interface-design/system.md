## 아이콘
기본은 Lucide(`lucide-react`, ISC). 예외적으로 Lucide에 없는 아이콘(농구공)은 Tabler Icons(MIT)에서 같은 규격(24x24 viewBox, stroke-width 2, round cap/join)의 SVG를 그대로 가져와 컴포넌트로 감쌌다 — 다른 라이브러리를 섞을 땐 반드시 이 규격이 맞는지 먼저 확인한다. `LucideIcon` 타입(`ForwardRefExoticComponent`)에 맞춰야 하므로 커스텀 아이콘 컴포넌트는 반드시 `forwardRef`로 감싼다(안 그러면 `TASK_ICONS: Record<string, LucideIcon>` 타입체크가 깨진다). 할 일 아이콘 화이트리스트는 `src/lib/icons.tsx`의 `TASK_ICONS`에 고정 — 임의로 추가하지 말고 여기서 관리한다. 하트·별은 v1.3.0에서 노트북(`laptop`)·금지(`ban`)로 교체했다(둘 다 Lucide).

## 오늘 탭 — 섹션 접힘/드래그, 항목 인라인 편집
- **두 섹션(고정/오늘만) 순서 바꾸기**(`src/screens/TodayScreen.tsx`의 `useSectionReorder`): 섹션이 딱 2개뿐이라 "정렬"이 아니라 "맞바꾸기"로 구현했다. 드래그 중인 섹션만 `transform: translateY()`로 손가락을 따라가고, 상대 섹션은 드래그된 섹션 높이의 절반을 넘어오면 자기 자리로 `transform`해 비켜준다. 실제 DOM 순서(= `settings.todaySectionOrder`)는 손을 뗄 때만 커밋한다 — 드래그 중에는 transform만 바뀌므로 리플로우 없이 부드럽다. `setPointerCapture`는 브라우저에 따라 예외를 던질 수 있어 반드시 `try/catch`로 감싼다.
- **길게 누르기 삭제**(`useLongPress`): 8px 넘게 움직이면 스크롤 의도로 보고 취소한다. 삭제 확인은 `src/components/ui/dialog.tsx`(Base UI Dialog, `--popover`/`--popover-foreground` 토큰이 카드 색과 이미 맞춰져 있어 커스텀 스타일 없이도 앱 톤과 어울린다)를 그대로 쓴다.
- **이름 탭 = 인라인 편집, 아이콘 탭 = 아이콘 변경 시트.** 완료 버튼은 별도 원형 버튼이라 이 둘과 히트 영역이 겹치지 않는다. 아이콘 그리드는 `src/components/IconPicker.tsx`로 분리해 `TaskAddSheet`와 오늘 탭의 "아이콘 변경" 시트가 공유한다.

## 설정 탭 — 마음가짐 문구 목록 (N개 자유 순서 드래그)
- **`useListReorder`**(`src/screens/SettingsScreen.tsx`) — 오늘 탭의 `useSectionReorder`는 항목이 정확히 2개일 때만 성립하는 "맞바꾸기" 로직이라, 임의 개수인 문구 목록에는 그대로 못 쓴다. 대신 드래그 시작 시 목록의 모든 행 위치(`getBoundingClientRect`)를 한 번에 스냅샷으로 저장해두고, 드래그 중에는 그 스냅샷만 기준으로 다른 행들의 이동 여부를 계산한다(매 프레임 레이아웃을 다시 읽지 않아 가볍다) — 손을 놓으면 "드래그된 항목의 현재 위치"와 "나머지 항목들의 원래 위치"를 한데 모아 중심점 기준으로 정렬해 최종 순서를 만들고 그걸로 커밋한다. 드래그 중인 행은 `translateY(dragY)`로 손가락을 따라가고, 다른 행은 드래그된 행이 자신의 중심을 넘어섰을 때만 드래그된 행 높이만큼 비켜준다(150ms 트랜지션).
- 행 레이아웃: [드래그 손잡이(`GripVertical`, 24px 히트 영역)] [색 동그라미 20px(`h-5 w-5`)] [문구 텍스트, 탭하면 인라인 `<input>`으로 전환] [삭제(`Trash2` 14px)] 순서. 손잡이에만 `touch-action: none`을 줘서 스크롤과 경합하지 않는다(오늘 탭 섹션 드래그와 같은 원칙).

## 진입 흐름 — 공용 크로스페이드
- **`App.tsx`의 `goTo(next)`**: 스플래시→팝업→랜딩으로 이어지는 모든 phase 전환을 이 함수 하나로 통일한다. `visible` 불리언 하나로 바깥 래퍼의 `opacity`/`transition-duration`만 제어하고, 안쪽 내용(phase별 컴포넌트)은 조건 분기로 스위치한다 — 화면마다 각자 페이드를 구현하지 않는다. 순서: `setVisible(false)`(300ms 페이드아웃) → `setTimeout`으로 phase 교체(아직 `visible=false`라 새 내용이 투명 상태로 마운트됨) → 150ms 정지 → `setVisible(true)`(300ms 페이드인). 이 정지 구간은 배경색 하나만 보여야 하며, 스플래시(로고) 컴포넌트를 다시 마운트해서 "재사용"하면 안 된다(GitHub_PWA/CLAUDE.md "진입 화면(스플래시) 전환은 페이드로 잇는다" 참고).
- 최초 진입(앱을 콜드 스타트로 열 때 첫 스플래시 자체)에는 이 페이드를 적용하지 않는다 — `visible` 초기값이 `true`라 스플래시가 즉시 뜬다. 페이드는 phase가 **바뀔 때만** 발동한다.

## 기록 탭 — 세그먼트 스와이프 캐러셀
- **`useSwipeCarousel`**(`src/screens/RecordScreen.tsx`): 세그먼트 4개(전체/프로젝트별/오늘만/고정 항목별)를 감싸는 `overflow-hidden` 래퍼 안에 `flex` 스트립을 두고, `translateX(calc(-index*100% + dragX))`로 위치를 잡는다. 가로 이동이 세로보다 뚜렷해지는 시점(6px)에만 스와이프로 확정(`axisRef`)하고, 그 전까지는 세로 스크롤을 그대로 둔다. 폭의 22%를 넘겨야 다음/이전으로 커밋하고, 못 넘기면 원래 자리로 스냅백. 첫/마지막 세그먼트를 넘어가려는 드래그는 0.35배로 눌러 고무줄 저항을 준다.
  - **버그로 확인된 것: pointerup의 판정을 `dragX` state로 하면 안 된다.** 리액트 state는 렌더 배치를 거치므로, pointermove 여러 번과 pointerup이 짧은 시간 안에 몰리면 아직 커밋 안 된 값을 읽어 "분명히 끝까지 끌었는데 원위치로 스냅백"하는 오류가 났다. `dragXRef`(ref)를 따로 두고 pointermove에서 state와 함께 갱신해, pointerup은 반드시 이 ref에서 최종값을 읽게 고쳤다.
  - **스와이프 뒤 오탭 방지**: 실제로 10px 넘게 끌렸으면 `suppressClickRef`를 세워, 스와이프가 끝난 자리에 있던 버튼(날짜 칸 등)의 다음 클릭 한 번을 `onClickCapture`에서 삼킨다.
  - 4개 세그먼트 모두 **같은 `cells`(월 그리드)** 를 쓰기 때문에 칸 개수·크기가 항상 동일하다 — 그래서 세그먼트마다 내용 높이가 달라져도(프로젝트별/고정 항목별에만 있는 칩 선택 줄 등) 스와이프 스트립 자체(달력 카드)의 높이는 절대 흔들리지 않는다. 칩 선택 줄과 날짜 상세 패널은 애초에 스트립 **바깥**(확정된 세그먼트 기준으로만 렌더)에 둬서, 변동 높이 문제를 원천적으로 피했다.
  - 세그먼트 탭의 흰 알약(pill)은 `absolute` + `translateX(progress * 100%)`로 스트립과 같은 `progress`(= `index - dragX/width`)를 공유해, 스와이프 중에도 pill이 손가락을 따라 같은 속도로 움직인다.

## 기록 탭 — 년·월 스크롤 휠 피커
- **`src/components/YearMonthPicker.tsx`의 `WheelColumn`**: 커스텀 드래그 물리 없이 네이티브 `scroll-snap-type: y mandatory` + `scroll-snap-align: center`로 만든 휠이다. 항목 높이 44px, 5개(위 2·가운데 1·아래 2)가 보이도록 컨테이너 220px, 위아래 패딩 88px((220-44)/2)로 첫/마지막 항목도 가운데까지 스크롤되게 한다. 스크롤이 멎으면(120ms 디바운스) `scrollTop / 44`를 반올림해 가운데 온 항목을 확정한다. 항목을 직접 탭하면 `scrollTo({behavior:"smooth"})`로도 이동할 수 있다.
- **겪은 버그: 가운데 강조 배경이 텍스트를 가렸다.** 가운데 칸을 표시하는 `bg-secondary` 박스를 `position: absolute`로 얹고 스크롤 리스트는 평범한 정적(static) 배치로 뒀는데, **CSS 스태킹 규칙상 포지셔닝된 요소(absolute)는 z-index가 없어도 항상 정적 in-flow 콘텐츠보다 위에 그려진다** — DOM 순서와 무관하게 강조 박스가 텍스트 위를 덮어버려 가운데 항목만 통째로 안 보였다. 스크롤 리스트 쪽에 `relative z-10`을 줘서 포지셔닝된 요소로 만들고, 강조 박스는 `z-0`으로 낮춰 순서를 명시적으로 고정해 해결했다. **absolute 요소와 static 요소를 겹쳐 쌓을 때는 항상 이 규칙을 의심할 것.**
- 시트는 `BottomSheet`(vaul) 재사용, 저장 버튼으로만 확정하고 시트를 아래로 밀면 취소된다(기존 원칙과 동일).

## 설정 탭 — 아코디언(그 자리에서 펼치기) vs 서브페이지
- 두 가지 "더 보기" 패턴을 구분해서 쓴다. **전체 초기화·설치 방법**처럼 짧고 한 번 보고 닫는 내용은 `ClickRow`를 토글 버튼으로 써서 같은 카드 안에 펼친다(`expanded` prop이 있으면 화살표가 90도 회전해 "펼쳐짐"을 알린다) — 새 화면으로 전환되는 느낌 없이 제자리에서 끝난다. **동기화·문구 편집·라이선스**처럼 내용이 길거나 자체 상호작용(입력·버튼)이 많은 것은 지금처럼 별도 서브페이지(`< 뒤로` 헤더)로 유지한다. 기준: 내용이 한 화면 스크롤 안에 편하게 들어오고 되돌아갈 필요가 없으면 아코디언, 아니면 서브페이지.

## 탭 헤더 구조 (5탭 공통)
모든 탭이 [부제목 → 제목 → (선택) 요약] 3단 구조를 공유한다(`mockup/design-mockup-v13.html`에서 승인, v1.3.1 구현).
- 부제목: `text-[11.5px] font-medium text-ink-soft`, `mb-0.5`. 오늘 탭만 실제 날짜(고유 기능이라 예외), 나머지는 `useSubtitle(navKey)` 훅으로 영어/한국어를 언어 설정에 따라 반전해서 보여준다.
- 제목: `text-[21px] font-bold tracking-tight`. 5탭 전부 이 크기로 통일(이전엔 오늘 탭만 21px, 나머지 19px이었다).
- 요약(선택): `text-[11px] font-medium text-ink-faint`, `mt-1`. 오늘 탭의 "오늘 n개 중 n개 완료", 기록 탭의 "전체 보기"/프로젝트명/항목명이 여기 해당 — 기록 탭에서는 이전에 19px 큰 제목이었던 걸 이 크기로 낮추고, "기록"이라는 고정 텍스트가 제목 역할을 대신 맡게 했다.
- 감싸는 wrapper는 `relative py-1.5 pb-3` 하나로 통일 — 부제목·제목·요약 사이 간격은 각각의 `mb-0.5`/`mt-1`로만 주고, 다음 섹션과의 간격은 wrapper의 `pb-3` 하나로 처리한다(이전엔 요소마다 따로 마진을 줘서 탭마다 간격이 미묘하게 달랐다).
